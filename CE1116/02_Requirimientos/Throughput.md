## 📚 Idea/Concepto 
El throughput, o rendimiento, es básicamente cuántas tareas, transacciones o datos puede procesar el sistema por segundo. Es un requisito no funcional que marca si el sistema aguanta el ritmo cuando hay mucha carga y usuarios al mismo tiempo. Para mejorar el throughput hay que cazar los cuellos de botella (ya sea el CPU, disco o red) y meterle mano con escalado horizontal, más hilos o procesos y aprovechar todo el hardware posible. Esto se revisa con métodos como ATAM para asegurarse de que la arquitectura no se quede corta, y siempre hay que decidir hasta dónde llegar, porque subir el throughput puede aumentar la latencia o el costo. Si no se mide bien y no se documentan las decisiones, el sistema puede fallar justo cuando más se necesita.
